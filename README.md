# Конвертер таблиць (TableConverter)

Безкоштовний застосунок для Windows, який бере рахунок, накладну чи акт — Excel, PDF з текстом, скан або фото — знаходить у ньому таблицю з товарами та реквізити документа (номер, дата, постачальник, договір, суми) і зберігає результат у CSV, Excel або JSON. Корисний усім, хто переносить дані з документів постачальників в облікові програми, таблиці чи скрипти, зокрема для імпорту в 1С.

## Можливості

- **Джерела**: Excel (`.xlsx`, `.xlsm`, `.xls`, усі аркуші), PDF з текстовим шаром (друковані форми 1С, банківські виписки тощо), а також **скани й фото** (`.jpg`, `.png`, `.tif`, скан-PDF) через розпізнавання тексту — див. розділ «Скани й фото».
- **Друковані форми в Excel**: рахунок чи накладна, збережені в Excel (з заголовком і реквізитами зверху, об'єднаною шапкою таблиці, підсумками знизу, вузькими «технічними» колонками), розпізнаються як форма: таблиця береться з аркуша (шапка, товари; кількість і одиниця, що лежать під однією об'єднаною шапкою, стають окремими колонками), а реквізити (номер, дата, постачальник і його ЄДРПОУ/ІПН, договір, суми «Разом / ПДВ / Разом з ПДВ») — з комірок поза таблицею. Форми, де кожен товар займає два рядки (ціна й сума без ПДВ, під ними з ПДВ), складаються в один рядок із колонками «без ПДВ» і «з ПДВ». У формах зі знижкою (кілька колонок ціни й суми) обираються ті, що узгоджуються: кількість × ціна = сума.
- **Пошук таблиць у PDF**: за лініями рамок, за вирівнюванням тексту (таблиці без ліній) або автоматично. Таблиця, що триває на наступних сторінках, склеюється в одну (повторювана шапка прибирається). Об'єднані комірки (наприклад, шапка «Кількість» над двома колонками) розпізнаються; заголовок документа й підсумок усередині рамки таблиці відкидаються.
- **Збереження в CSV, Excel або JSON**:
  - **CSV** з очищенням (див. нижче) і підбором вільного роздільника.
  - **Excel** без очищення: для PDF — «1 в 1» (заголовок, реквізити, таблиця з рамками й об'єднаннями, підписи; кожна сторінка — аркуш) або лише таблиця.
  - **JSON** — шапка документа й усі рядки товарів в одному файлі (див. розділ «Формат JSON»).
- **Вільний роздільник CSV**: застосунок аналізує символи даних і показує, які роздільники в цих даних не зустрічаються (`Tab`, `^`, `~`, `§`, `#`, `@` тощо), з кількістю входжень для решти. Обраний роздільник підставляється в поле, його можна замінити власним символом.
- **Очищення CSV**: переноси рядків у клітинках → пробіл; лапки `"` → апостроф; порожні рядки в кінці відкидаються; числа нормалізуються (`3 600,00` → `3600.00`); для об'єднаної шапки колонки отримують унікальні назви (`Кількість`, `Кількість_2`). Кожну опцію можна вимкнути.
- **Профілі колонок**: фіксована розкладка колонок для імпорту, авто-підбір колонок за заголовками (в т.ч. за вмістом: кількість × ціна = сума), збереження вибору для постачальника.
- **Помічник** (вікно з трьома вкладками): реквізити документа з кнопками копіювання, контроль розпізнаної таблиці (збіг сум, кількості позицій), підказки для налаштування імпорту.
- **Автооновлення** з цього репозиторію (див. нижче).

## Як користуватися

1. Оберіть файл (Excel, PDF, скан або фото) — таблиця й реквізити розпізнаються автоматично.
2. Оберіть потрібні таблиці зі списку (для PDF можна змінити режим пошуку таблиць).
3. Оберіть формат: CSV (профіль колонок, роздільник, очищення), Excel або JSON. Показуються лише параметри вибраного формату; нижче — прев'ю результату.
4. У **Помічнику → Контроль** перевірте, що сума по рядках збігається з «Разом» документа, а кількість позицій — із «Всього найменувань». Якщо є ✗, виправте підбір колонок кнопкою «Колонки…» або виберіть інший режим пошуку таблиць.
5. Натисніть **«Зберегти…»**.

Підбір колонок для постачальника можна зберегти кнопкою «Зберегти для постачальника» (ключ — його ІПН або ЄДРПОУ з документа): наступного разу для цього постачальника підбір підставиться сам. Файл налаштувань: `%APPDATA%\TableConverter\profiles.json`.

Порядок колонок профілів:

- **Керовані форми 1С (17 колонок)**: Код, Артикул, Штрихкод, Наименование, Комментарий, Количество, Единица, УКТВЭД, Вес, Объем, Высота, Длина, Ширина, Коэффициент, Цена, Сумма, ХарактеристикаНаименование.
- **Звичайні форми 1С (19 колонок)**: НомерСтроки, Код, КодКонтрагента, Артикул, ШтрихКод, НаименованиеКонтрагента, Наименование, Характеристика, Серия, ДопОписание, Количество, Единица, УКТВЭД, ВесЕдиницы, ОбъемЕдиницы, Коэффициент, Цена, Сумма, ПроцентСкидкиНаценки.

У CSV за профілем кількість виводиться цілою (`1,000` → `1`), справжні дробові значення лишаються як є (`2.25`); рядки «Разом» усередині таблиці виключаються.

## Формат JSON

Файл містить і шапку документа, і таблицю з підібраними колонками, тож програма, що його читає, не потребує налаштування колонок і роздільника. Формат відкритий: його може прочитати будь-який скрипт чи система.

**Структура** (UTF-8 без BOM; ключі російською, як імена реквізитів у 1С; дати ISO; числа — числа JSON; порожні поля не пишуться):

```json
{
 "Формат": "TableConverter",
 "ВерсияФормата": 1,
 "Источник": {"Файл": "накладна.pdf", "Тип": "pdf", "Программа": "TableConverter 1.4.3"},
 "Шапка": {
  "ВидДокумента": "Видаткова накладна",
  "Номер": "НФ-277",
  "Дата": "2026-09-23T00:00:00",
  "ДатаТекст": "23.09.2026",
  "Поставщик": {"Наименование": "ТОВ \"Ромашка\"", "ЕДРПОУ": "12345678", "IBAN": "UA21..."},
  "Покупатель": {"Наименование": "ФОП Іванов І. І.", "ИНН": "1234567890"},
  "Договор": {"Представление": "№ 64 від 01.03.2023", "Номер": "64", "Дата": "2023-03-01T00:00:00"},
  "Склад": "Основний",
  "Итоги": {"Сумма": 2255, "СуммаНДС": 0, "СуммаСНДС": 2255, "КоличествоПозиций": 1}
 },
 "Товары": [
  {"НомерСтроки": 1, "Артикул": "A-1", "Наименование": "Мило", "Количество": 2, "Единица": "шт", "Цена": 10.5, "Сумма": 21}
 ],
 "Контроль": [{"Уровень": "ok", "Сообщение": "Позицій у таблиці: 1."}],
 "Дополнительно": {"КодыВТексте": "ЄДРПОУ 12345678", "IBANВТексте": "UA21..."}
}
```

`Уровень` у `Контроль` — `ok`, `warn` або `error`. Якщо обрано кілька таблиць, їхні рядки об'єднуються в один список `Товары`. Текст зберігається без очищення (лапки й символи не змінюються), колонки підбираються за профілем керованих форм 1С (можна виправити кнопкою «Колонки…»). У рядках товарів пишуться лише знайдені поля: `Код`, `Артикул`, `Штрихкод`, `Наименование`, `Комментарий`, `Единица`, `УКТВЭД`, `Количество`, `Цена`, `Сумма`.

## Скани й фото

Скан-PDF (без текстового шару) та зображення (`.jpg`, `.jpeg`, `.png`, `.bmp`, `.tif`, `.tiff`) розпізнаються автоматично, усе локально (файли нікуди не надсилаються). Далі діє той самий розбір: пошук таблиці за координатами слів, реквізити, профілі, контроль.

**Два рушії розпізнавання.** У вікні програми, у рядку «Розпізнавання сканів і фото (OCR)», завжди видно, який доступний:

- **Рушій для української** (рекомендовано): RapidOCR з моделлю PP-OCRv5 для кирилиці. Читає українські «і/ї/є/ґ», сам виправляє нахил, працює офлайн, права адміністратора не потрібні. Це окремий пакет (≈130 МБ), що завантажується кнопкою **«Встановити»** (зелений напис — встановлено). Пакет лежить у [релізі `ocr-pack`](../../releases/tag/ocr-pack), зберігається в `%LOCALAPPDATA%\TableConverter\ocr`.
- **Windows OCR** (запасний, вбудований у Windows 10/11): працює одразу, але не вміє українські «і/ї/є/ґ» (слова з ними зникають або спотворюються; пакета української для нього в Windows немає, а болгарська й сербська кирилиця читають так само, як російська). Якщо рушія для української не встановлено, застосунок використовує його й попереджає про це.

Що враховано:

- нахил фото виправляється автоматично, перед розпізнаванням вирівнюється контраст (допомагає на фото з нерівним освітленням);
- **українські літери** виправляються за словником: слово, якого немає в українському словнику, замінюється варіантом із заміною `и↔і`, `е↔є`, `і↔ї`, `г↔ґ`, якщо такий варіант у словнику рівно один (`ФИЗИЧНА` → `ФІЗИЧНА`, `правільність` → `правильність`). Працює лише для документів з українськими літерами; коди, артикули, латиниця й короткі абревіатури не змінюються. Кількість виправлень показується в повідомленні після розпізнавання;
- виправляються типові помилки розпізнавання: `NQ` → `№`, літери замість цифр у числах (`з 600,00` → `3 600,00`), слова шапки й одиниці, прочитані латинськими двійниками (`p06iT` → `робіт`, `шT` → `шт`), змішані кирилиця й латиниця в словах (`вiд` → `від`);
- рядки таблиці, які OCR прочитав погано (порожня чи зіпсована назва, немає коду, кількість × ціна ≠ сума), розпізнаються ще раз окремо, смугою зображення; слова, що в документі трапляються кілька разів і відрізняються однією літерою від частого слова, вирівнюються за ним ('попімерпіщаний' → 'полімерпіщаний');
- заголовки з помилками розпізнавання шукаються нечітко, а коли їх не прочитано зовсім — колонки кількості й ціни визначаються за вмістом (кількість × ціна = сума);
- таблиця друкованої форми (акт виконаних робіт, рахунок, накладна) шукається за ключовими словами шапки й за вмістом рядків, тож розпізнається навіть з одним рядком; підтримуються кілька колонок цін і сум (без ПДВ / з ПДВ), одиниця виду «100 шт» і назви товарів на кілька рядків; рядок «Разом» у таблицю не потрапляє; печатки й підписи, що дають «сміттєві» таблиці, не обираються за замовчуванням;
- коли сторони в документі не підписані (акт: «Від Виконавця / Від Замовника»), у **Реквізитах** зводяться всі знайдені коди ЄДРПОУ/ІПН і рахунки IBAN, щоб їх можна було скопіювати.

**Обмеження.** OCR помиляється, особливо на фото: можливі втрачені літери й спотворені цифри. Тому після кожного розпізнавання перегляньте вкладку **Контроль** (збіг суми з «Разом», кількості позицій, перевірка кількість × ціна = сума ловить більшість помилок цифр) і прев'ю. Для хорошого результату знімайте рівно, при добрім освітленні, щоб увесь документ був у кадрі. Excel із сканів зберігається лише як таблиця. Один скан-аркуш розпізнається ≈7–10 с (перший запуск довший).

**Збирання пакета рушія** (потрібне лише розробнику): `python build_ocr_pack.py` створює `dist/TableConverter-OCR.zip` (`ocr_worker.exe` + `version.txt`; потрібен інтернет). Файл завантажується в реліз із тегом `ocr-pack`:

```powershell
gh release create ocr-pack dist\TableConverter-OCR.zip --title "OCR-пакет" --notes "Рушій розпізнавання для української"
gh release upload ocr-pack dist\TableConverter-OCR.zip --clobber   # оновлення пакета
```

## Вимоги

- Windows 10/11
- Для запуску зібраного `TableConverter.exe` нічого встановлювати не потрібно
- Інтернет — лише для перевірки оновлень і завантаження рушія розпізнавання; без нього застосунок повністю працює

## Встановлення

Завантажте `TableConverter.exe` з [Releases](../../releases/latest) і запустіть. Один файл, без залежностей.

## Запуск із вихідного коду і збірка

```powershell
pip install -r requirements.txt
python app.py
```

Збірка exe (PyInstaller):

```powershell
.\build.bat
```

Результат — `dist\TableConverter.exe`.

## Тести

Тести самодостатні (для генерації тестових файлів потрібні `reportlab` і `xlwt`: `pip install reportlab xlwt`; тест сканів використовує Windows OCR і пропускається без нього):

```powershell
python test_app.py         # Excel -> CSV
python test_pdf.py         # PDF: таблиці, об'єднання, Excel 1 в 1
python test_docinfo.py     # реквізити документа
python test_profiles.py    # профілі, підбір колонок, контроль, підказки
python test_excelforms.py  # друковані форми в Excel (.xlsx і .xls)
python test_jsonexport.py  # JSON: шапка, товари, типи
python test_scanforms.py   # таблиці-форми зі сканів: кілька цін/сум, одиниця "100 шт"
python test_ukfix.py       # виправлення українських літер за словником
python test_scans.py       # скани й фото (OCR)

python test_updater.py     # версії та самооновлення
```

## Автооновлення — як це працює

При кожному запуску застосунок тихо звіряє власну версію з файлом [`version.txt`](version.txt) у гілці `main` (`raw.githubusercontent.com`, HTTPS, без токена). Якщо версія новіша, номер версії внизу праворуч стає помаранчевим (`v1.0.0 ↑`), без спливаючого вікна. Клік по ньому пропонує оновитися; якщо клікнути, коли оновлень немає, застосунок перевірить ще раз і повідомить результат.

Після згоди застосунок завантажує новий `TableConverter.exe` з [останнього релізу](../../releases/latest), завершується, і невеликий скрипт підміняє файл та запускає нову версію. Поруч із версією є посилання на цей репозиторій.

Щоб випустити нову версію:

1. Підняти номер **в обох місцях**: `version.txt` і `APP_VERSION` у `app_version.py` (`test_updater.py` перевіряє, що вони збігаються).
2. Зібрати exe (`build.bat`), закомітити зміни в `main`.
3. Створити реліз із тегом `vX.Y.Z` і прикріпленим `dist\TableConverter.exe`:

```powershell
gh release create vX.Y.Z dist\TableConverter.exe --title "vX.Y.Z" --notes "що змінилось"
```

## Примітки

- Застосунок працює локально: файли нікуди не надсилаються. Єдині мережеві запити — перевірка `version.txt` і (за згодою) завантаження оновлення чи рушія розпізнавання.
- Розпізнавання таблиць — евристичне. Завжди звіряйте результат за вкладкою **Контроль**; для таблиць без ліній, з об'єднаними комірками або дуже нестандартних форм підбір колонок може потребувати ручного виправлення.
- Реквізити документа (номер, дата, сторони, договір, суми) зчитуються з тексту першої сторінки за правилами для українських і російських друкованих форм; для інших форм поля можуть не знайтися.
