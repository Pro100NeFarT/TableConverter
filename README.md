# Конвертер таблиць (TableConverter)

Невеликий застосунок для Windows: бере Excel або PDF з текстовим шаром, знаходить таблицю й зберігає її в CSV чи Excel. Створений для операторів і адміністраторів, які завантажують накладні та прайс-листи в 1С обробками **УпрИмпортИзExcel** і **ИмпортИзExcel**: готує файл так, щоб обробка прочитала його без зсувів колонок, а також підказує, що вводити в її налаштуваннях.

![Python](https://img.shields.io/badge/Python-3.13%2B-blue) ![Windows](https://img.shields.io/badge/Windows-10%2F11-0078D6)

## Можливості

- **Джерела**: Excel (`.xlsx`, `.xlsm`, `.xls`, усі аркуші), PDF з текстовим шаром (друковані форми 1С, банківські виписки тощо), а також **скани й фото** (`.jpg`, `.png`, `.tif`, скан-PDF) через розпізнавання тексту — див. розділ «Скани й фото».
- **Друковані форми в Excel**: рахунок чи накладна 1С, збережені в Excel (з заголовком і реквізитами зверху, об'єднаною шапкою таблиці, підсумками знизу, вузькими «технічними» колонками), розпізнаються як форма: таблиця береться з аркуша (шапка, товари; кількість і одиниця, що лежать під однією об'єднаною шапкою, стають окремими колонками), а реквізити (номер, дата, постачальник і його ЄДРПОУ/ІПН, договір, суми «Разом / ПДВ / Разом з ПДВ») — з комірок поза таблицею. У формах зі знижкою (кілька колонок ціни й суми) обираються ті, що узгоджуються: кількість × ціна = сума, права пара — після знижки.
- **Пошук таблиць у PDF**: за лініями рамок, за вирівнюванням тексту (таблиці без ліній) або автоматично. Таблиця, що триває на наступних сторінках, склеюється в одну (повторювана шапка прибирається). Об'єднані комірки (наприклад, шапка «Кількість» над двома колонками) розпізнаються.
- **Збереження в CSV, Excel або JSON**:
  - **CSV** проходить очищення під 1С (див. нижче).
  - **JSON (для 1С)** — шапка документа (номер, дата, постачальник із кодами, договір, суми) і всі рядки товарів в одному файлі; обробка **УпрИмпортИзExcel** читає його й одразу заповнює шапку та таблицю (див. розділ «JSON для УпрИмпортИзExcel»).
  - **Excel** зберігається без очищення: для PDF — «1 в 1» (заголовок, реквізити, таблиця з рамками й об'єднаннями, підписи; кожна сторінка — аркуш) або лише таблиця.
- **Вільний роздільник CSV**: застосунок аналізує символи даних і показує, які роздільники в цих даних не зустрічаються (`Tab`, `^`, `~`, `§`, `#`, `@` тощо), з кількістю входжень для решти. Можна ввести власний символ.
- **Очищення CSV**: переноси рядків у клітинках → пробіл; лапки `"` → апостроф; порожні рядки в кінці відкидаються; числа нормалізуються (`3 600,00` → `3600.00`); для об'єднаної шапки колонки отримують унікальні назви (`Кількість`, `Кількість_2`). Кожну опцію можна вимкнути.
- **Профілі для 1С**: розкладка колонок обробки, авто-підбір колонок за заголовками, збереження вибору для постачальника.
- **Помічник** (вікно з трьома вкладками): реквізити документа з кнопками копіювання, контроль розпізнаної таблиці, готові налаштування для обробки 1С.
- **Автооновлення** з цього репозиторію (див. нижче).

## Робота з обробками 1С

### Що за обробки

| | УпрИмпортИзExcel | ИмпортИзExcel |
|---|---|---|
| Для чого | керовані форми (УНФ / «Малий бізнес», BASSmallBusiness) | звичайні форми (УТ/УТП для України) |
| CSV | `СформироватьТЗ(Файл, 1, РазделительCSV)`: рядок 1 — заголовок, роздільник задається полем «Роздільник csv» на вкладці «Настройка» (зберігається разом з налаштуваннями постачальника) | роздільник за замовчуванням `;`; якщо вказати `,`, використовується окремий розбір із лапками (UTF-8) |
| Excel | `.xls`/`.xlsx` як табличний документ | `.xls`/`.xlsx`: платформа 1С, Excel COM або компонента MiracleV8 |
| Колонки | за **номером** колонки, 17 за замовчуванням | за **номером** колонки, 19 за замовчуванням |
| Результат | документ (за замовчуванням приходна накладна) або номенклатура, ціни, характеристики | новий документ (за замовчуванням `ПоступлениеТоваровУслуг`) або дописування в існуючий, форма відкривається без запису |

Порядок колонок за замовчуванням:

- **УпрИмпортИзExcel (17)**: Код, Артикул, Штрихкод, Наименование, Комментарий, Количество, Единица, УКТВЭД, Вес, Объем, Высота, Длина, Ширина, Коэффициент, Цена, Сумма, ХарактеристикаНаименование.
- **ИмпортИзExcel (19)**: НомерСтроки, Код, КодКонтрагента, Артикул, ШтрихКод, НаименованиеКонтрагента, Наименование, Характеристика, Серия, ДопОписание, Количество, Единица, УКТВЭД, ВесЕдиницы, ОбъемЕдиницы, Коэффициент, Цена, Сумма, ПроцентСкидкиНаценки.

Для Excel-шляху обидві обробки мають однакові налаштування на вкладці «Настройка»: `НомерЛиста`, `ПерваяСтрокаСТоваром` (за замовчуванням 16), `ПоследняяСтрокаСТоваром`, `КоличествоСтрокПодвала`, `КоличествоКолонок`, `ШагКолонок`.

### Типовий сценарій оператора

1. Відкрити PDF (або Excel) постачальника у застосунку — таблиця й реквізити документа розпізнаються автоматично.
2. У вікні **Помічника → Контроль** перевірити, що сума по рядках збігається з «Разом» документа, а кількість позицій — із «Всього найменувань». Якщо є ✗, виправити підбір колонок кнопкою «Колонки…» або вибрати інший режим пошуку таблиць.
3. Вибрати **профіль** («УпрИмпортИзExcel» або «ИмпортИзExcel»), натиснути «Аналізувати» (роздільник `;` вибирається сам) і **«Зберегти…»** CSV. Для Excel-шляху обробки — зберегти Excel (1 в 1 або лише таблицю).
4. У вікні **Помічника → Налаштування для 1С** (відкривається після збереження) побачити, що ввести в обробці:
   - для CSV: роздільник csv і порядок колонок (достатньо «Колонки за замовчуванням»);
   - для Excel: `НомерЛиста`, `ПерваяСтрокаСТоваром`, `ПоследняяСтрокаСТоваром` (або `КоличествоСтрокПодвала`) і номери колонок для Наименование, Количество, Единица, Цена, Сумма.
5. У документі, який створюється в 1С, скопіювати потрібні реквізити (номер і дату постачальника, суму, ІПН/ЄДРПОУ для пошуку контрагента, договір) кнопками **Помічника → Реквізити**.

Підбір колонок для постачальника можна зберегти кнопкою «Зберегти для постачальника» (ключ — його ІПН або ЄДРПОУ з документа). Наступного разу для цього постачальника підбір підставиться сам. Файл налаштувань: `%APPDATA%\TableConverter\profiles.json`.

### Що застосунок робить за обробку

Особливості обробок, які застосунок враховує при підготовці файлу:

| Особливість обробки | Що робить застосунок |
|---|---|
| Файл читається рядок за рядком, поле з переносом рядка ламає запис | переноси рядків у клітинках → пробіл |
| Закриття поля в лапках шукається як `";` незалежно від роздільника | лапки в тексті → апостроф, жодне поле не потребує лапок; `;` у тексті → `,` |
| Порожні рядки в кінці аркуша дають зайві записи | порожній «хвіст» відкидається |
| Колонки беруться за номером | фіксована розкладка профілю: порядок і кількість колонок завжди однакові |
| `Количество` читається як ціле (`ТолькоЦифры` / `УбратьБуквы`), `1,000` → `1000` | кількість із нулями після коми виводиться цілою (`1,000` → `1`), справжні дробові значення лишаються як є (`2.25`) |
| Числа з пропусками й комою (`3 600,00`) | нормалізуються до `3600.00` |
| Рядок «Разом» усередині таблиці стане позицією | такі рядки виключаються з CSV |
| Об'єднана шапка (`Кількість` над кількістю й одиницею) дає порожню назву колонки | `Кількість`, `Кількість_2` |

### Що застосунок поки не вирішує (особливості самих обробок)

- Для CSV/Excel документ створюється з поточною датою (`ТекущаяДата()`), а `№ вх. документа`, `Дата вх. документа` й `Сума документа` не заповнюються — їх треба внести вручну; значення можна скопіювати з **Помічника → Реквізити**. Через JSON номер і дата вхідного документа підставляються самі (дата документа лишається поточною).
- Для CSV/Excel контрагент і договір обираються вручну; за ІПН/ЄДРПОУ з **Реквізитів** їх зручно знайти в довіднику. Через JSON обробка шукає їх сама.
- Захисту від повторного створення того самого документа в `УпрИмпортИзExcel` немає (у `ИмпортИзExcel` пропускаються лише рядки, що вже є в табличній частині).
- У `УпрИмпортИзExcel` поле «Роздільник csv» у вже збережених налаштуваннях постачальника порожнє — його треба ввести один раз і зберегти налаштування.

### JSON для УпрИмпортИзExcel

Формат **«JSON (для 1С)»** дає змогу не налаштовувати колонки, роздільник і рядки в обробці: файл містить і шапку документа, і таблицю з уже підібраними колонками.

**Як користуватися**

1. У застосунку оберіть файл і таблицю, перевірте **Помічник → Контроль**, оберіть формат «JSON (для 1С)» і збережіть.
2. В обробці **УпрИмпортИзExcel** у полі «Файл» оберіть `.json` і натисніть «Загрузить».
3. Обробка:
   - шукає **контрагента** за ЄДРПОУ/ІПН постачальника (у реквізитах `КодПоЕДРПОУ` та `ИНН`) і, якщо знайшла, підставляє його (разом з налаштуваннями контрагента, як при ручному виборі);
   - шукає **договір** контрагента за номером і датою з файлу;
   - заповнює `ТаблицаЭксель` (`Код`, `Артикул`, `Наименование` — разом із полями `…НоменклатурыКонтрагента`, `Штрихкод`, `Количество`, `Единица`, `УКТВЭД`, `Цена`, `Сумма`, `Комментарий`);
   - виконує звичайний пошук номенклатури за налаштуваннями пошуку;
   - виводить повідомлення про знайденого контрагента, кількість позицій і результат контролю з файлу (помилки й попередження);
   - при «Создать документ» додає до шапки `НомерВходящегоДокумента` і `ДатаВходящегоДокумента`.

Зміни в обробці зроблено лише в модулі форми (`Forms/Форма/Ext/Form/Module.bsl`, область `ЗагрузкаJSON`).

**Структура файлу** (UTF-8 без BOM; ключі російською, як імена реквізитів 1С; дати ISO для `ПрочитатьДатуJSON`; числа — числа JSON; порожні поля не пишуться):

```json
{
 "Формат": "TableConverter",
 "ВерсияФормата": 1,
 "Источник": {"Файл": "накладна.pdf", "Тип": "pdf", "Программа": "TableConverter 1.3.0"},
 "Шапка": {
  "ВидДокумента": "Видаткова накладна",
  "Номер": "НФ-277",
  "Дата": "2026-09-23T00:00:00",
  "ДатаТекст": "23.09.2026",
  "Поставщик": {"Наименование": "ТОВ \"Ромашка\"", "ЕДРПОУ": "12345678", "IBAN": "UA21..."},
  "Покупатель": {"Наименование": "ФОП Іванов І. І.", "ИНН": "1234567890"},
  "Договор": {"Представление": "№ 64 від 01.03.2023", "Номер": "64", "Дата": "2023-03-01T00:00:00"},
  "Склад": "Основний",
  "Итоги": {"Сумма": 2255, "СуммаНДС": 0, "СуммаСНДС": 2255, "КоличествоПозиций": 1}
 },
 "Товары": [
  {"НомерСтроки": 1, "Артикул": "A-1", "Наименование": "Мило", "Количество": 2, "Единица": "шт", "Цена": 10.5, "Сумма": 21}
 ],
 "Контроль": [{"Уровень": "ok", "Сообщение": "Позицій у таблиці: 1."}],
 "Дополнительно": {"КодыВТексте": "ЄДРПОУ 12345678", "IBANВТексте": "UA21..."}
}
```

`Уровень` у `Контроль` — `ok`, `warn` або `error`. Якщо обрано кілька таблиць, їхні рядки об'єднуються в один список `Товары`. У JSON текст зберігається без очищення (лапки й символи не змінюються), колонки підбираються за профілем «УпрИмпортИзExcel» (можна виправити кнопкою «Колонки…»).

## Скани й фото

Скан-PDF (без текстового шару) та зображення (`.jpg`, `.jpeg`, `.png`, `.bmp`, `.tif`, `.tiff`) розпізнаються автоматично, усе локально (файли нікуди не надсилаються). Далі діє той самий розбір: пошук таблиці за координатами слів, реквізити, профілі для 1С, контроль.

**Два рушії розпізнавання.** У вікні програми, у рядку «Розпізнавання сканів і фото (OCR)», завжди видно, який доступний:

- **Рушій для української** (рекомендовано): RapidOCR з моделлю PP-OCRv5 для кирилиці. Читає українські «і/ї/є/ґ», сам виправляє нахил, працює офлайн, права адміністратора не потрібні. Це окремий пакет (≈130 МБ), що завантажується кнопкою **«Встановити»** (зелений напис — встановлено). Пакет лежить у [релізі `ocr-pack`](../../releases/tag/ocr-pack), зберігається в `%LOCALAPPDATA%\TableConverter\ocr`.
- **Windows OCR** (запасний, вбудований у Windows 10/11): працює одразу, але не вміє українські «і/ї/є/ґ» (слова з ними зникають або спотворюються; пакета української для нього в Windows немає, а болгарська й сербська кирилиця читають так само, як російська). Якщо рушія для української не встановлено, застосунок використовує його й попереджає про це.

Що враховано:

- нахил фото виправляється автоматично;
- для Windows OCR виправляються типові помилки: `NQ` → `№`, `ј` → `і`, літери замість цифр у числах (`з 600,00` → `3 600,00`), слова шапки, прочитані латинськими двійниками (`p06iT` → `робіт`);
- заголовки з помилками розпізнавання шукаються нечітко, а коли їх не прочитано зовсім — колонки кількості й ціни визначаються за вмістом (кількість × ціна = сума);
- таблиця друкованої форми (акт виконаних робіт, рахунок) шукається за ключовими словами шапки (достатньо «Найменування» і «Сума») і за вмістом рядків, тож розпізнається навіть з одним рядком; рядок «Разом» у таблицю не потрапляє; печатки й підписи, що дають «сміттєві» таблиці, не обираються за замовчуванням;
- коли сторони в документі не підписані (акт: «Від Виконавця / Від Замовника»), у **Реквізитах** зводяться всі знайдені коди ЄДРПОУ/ІПН і рахунки IBAN, щоб їх можна було скопіювати.

**Обмеження.** OCR помиляється, особливо на фото: можливі втрачені літери й спотворені цифри (наприклад, перша велика «І» в слові, «год» → «род»). Тому після кожного розпізнавання перегляньте вкладку **Контроль** (збіг суми з «Разом», кількості позицій, перевірка кількість × ціна = сума ловить більшість помилок цифр) і прев'ю. Для хорошого результату знімайте рівно, при добрім освітленні, щоб увесь документ був у кадрі. Excel із сканів зберігається лише як таблиця. Один скан-аркуш розпізнається ≈7–10 с (перший запуск довший).

**Збирання пакета рушія** (потрібне лише розробнику): `python build_ocr_pack.py` створює `dist/TableConverter-OCR.zip` (`ocr_worker.exe` + `version.txt`; потрібен інтернет). Файл завантажується в реліз із тегом `ocr-pack`:

```powershell
gh release create ocr-pack dist\TableConverter-OCR.zip --title "OCR-пакет" --notes "Рушій розпізнавання для української"
gh release upload ocr-pack dist\TableConverter-OCR.zip --clobber   # оновлення пакета
```

## Встановлення

Завантажте `TableConverter.exe` з [Releases](../../releases/latest) і запустіть. Один файл, без залежностей.

## Запуск із вихідного коду і збірка

```powershell
pip install -r requirements.txt
python app.py
```

Збірка exe (PyInstaller):

```powershell
.\build.bat
```

Результат — `dist\TableConverter.exe`.

## Тести

Тести самодостатні (для генерації тестових файлів потрібні `reportlab` і `xlwt`: `pip install reportlab xlwt`; тест сканів використовує Windows OCR і пропускається без нього):

```powershell
python test_app.py        # Excel -> CSV
python test_pdf.py        # PDF: таблиці, об'єднання, Excel 1 в 1
python test_docinfo.py    # реквізити документа
python test_profiles.py   # профілі 1С, підбір колонок, контроль, підказки
python test_excelforms.py # друковані форми в Excel (.xlsx і .xls)
python test_jsonexport.py  # JSON для 1С: шапка, товари, типи
python test_scanforms.py   # таблиці-форми зі сканів: кілька цін/сум, одиниця "100 шт"
python test_scans.py      # скани й фото (OCR)
python test_ocr_engine.py # рушій для української: установка, виклик, індикатор у вікні
python test_updater.py    # версії та самооновлення
```

## Автооновлення — як це працює

При кожному запуску застосунок тихо звіряє власну версію з файлом [`version.txt`](version.txt) у гілці `main` (`raw.githubusercontent.com`, HTTPS, без токена). Якщо версія новіша, номер версії внизу праворуч стає помаранчевим (`v1.0.0 ↑`), без спливаючого вікна. Клік по ньому пропонує оновитися; якщо клікнути, коли оновлень немає, застосунок перевірить ще раз і повідомить результат.

Після згоди застосунок завантажує новий `TableConverter.exe` з [останнього релізу](../../releases/latest), завершується, і невеликий скрипт підміняє файл та запускає нову версію. Поруч із версією є посилання на цей репозиторій.

Щоб випустити нову версію:

1. Підняти номер **в обох місцях**: `version.txt` і `APP_VERSION` у `app_version.py` (`test_updater.py` перевіряє, що вони збігаються).
2. Зібрати exe (`build.bat`), закомітити зміни в `main`.
3. Створити реліз із тегом `vX.Y.Z` і прикріпленим `dist\TableConverter.exe`:

```powershell
gh release create vX.Y.Z dist\TableConverter.exe --title "vX.Y.Z" --notes "що змінилось"
```

## Примітки

- Застосунок працює локально: файли нікуди не надсилаються. Єдиний мережевий запит — перевірка `version.txt` і (за згодою) завантаження оновлення.
- Розпізнавання таблиць у PDF — евристичне. Завжди звіряйте результат за вкладкою **Контроль**; для таблиць без ліній, з об'єднаними комірками або дуже нестандартних форм підбір колонок може потребувати ручного виправлення.
- Реквізити документа (номер, дата, сторони, договір, суми) зчитуються з тексту першої сторінки за правилами для українських і російських друкованих форм 1С; для інших форм поля можуть не знайтися.
